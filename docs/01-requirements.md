# 01 · 需求说明书

## 1. 背景

26.11 期（11/10–12/15）要求产出不少于 15,000 条单轮 pointwise 反馈数据，每团队日 500–1500 条。
一条数据 = 一个 session = 一轮有效交互，附初始环境快照、产物快照、运行录屏、轨迹与 Feedback。

上一期的做法是 `sologsb-0917` 技能 + `sg-auto` 监控台：技能跑 Pair-wise GSB，监控台负责排队、限额、
拉起桌面会话、监看进度。本期形态变了（单轮 pointwise、单一 `auto` 模型、新增录屏与 19 列提交表），
原有监控台的表格、评分维度、候选 A/B 概念全部不适用。

同时本机新增了「工程台 Project Hub」（`http://localhost:8088`），题目来源从自建项目池转为工程台的
独占领取工程。这带来三个新约束：领取是排他且可回收的、工程以 ZIP 版本下发、来源地址必须可配置。

## 2. 目标

做一个**本地单机、单用户、可无人值守**的作业控制台，把 `solo-2611` 技能从「手工敲 11 条命令」变成
「看板驱动的流水线」，并保证：

1. 题源可配置、项目必须显式指定，绝不静默抓取或跨项目污染。
2. 每一步都有机器门禁，不通过就停在原地，不能「看起来过了」。
3. 所有事实（SessionID、PromptID、SHA、时长、录屏证据）从磁盘与技能输出直接读取，控制台不自造。
4. 一屏看清 20 题里哪题卡住、卡在哪一步、为什么。
5. 支持中断恢复：关掉控制台、重启电脑、容器被杀，重开后状态仍准确。

## 3. 非目标

| 不做 | 原因 |
|---|---|
| 生成或润色 Feedback 文案 | 规范要求可核验、无 AI 痕迹；且由标注专家负责，程序代写等于造假 |
| 自动给交付完整性打分 | 同上，分数必须由看过轨迹与产物的人给出 |
| 自研容器执行链路 | 技能已有 `run`/`interactive`/`collect`，复制一份必然漂移 |
| 替代工程台的上传、标签、用户管理 | 那是另一个系统的职责 |
| 多用户、远程访问、云部署 | 单机单用户，暴露面越小越好 |
| Windows 支持 | 录屏依赖 ScreenCaptureKit |

## 4. 角色

本期只有两个角色，但控制台要把二者的动作分开记录。

| 角色 | 能做什么 | 不能做什么 |
|---|---|---|
| **作业人**（唯一真实用户） | 指定项目、领取、选题、写题面、写 Feedback 草稿、选录屏窗口、导出 | —— |
| **外部 Agent**（Codex / Claude 等） | 在控制台打开的工作目录里起草题面草稿、读轨迹写 Feedback 草稿、填难度论证 | 不能改分数门禁规则、不能跳过录屏、不能直接写 Excel |
| **控制台程序** | 调技能、跑门禁、收证据、排版、留痕 | 不做判断题 |

这三者的边界是本设计的核心：程序只做「可机械判定」的事，凡是「要判断」的都留给人或 Agent，
但程序负责**证明判断所依据的事实成立**。

## 5. 功能需求

编号规则：`FR-<域><序号>`。MUST / SHOULD / MAY 按 RFC 2119 语义。

### 5.1 题源与领取（SRC）

| 编号 | 需求 | 级别 |
|---|---|---|
| FR-SRC-01 | 题源地址可配置，至少支持 `http://localhost:8088` 与任意同构地址；配置项含 base URL、认证方式、超时 | MUST |
| FR-SRC-02 | **项目必须显式指定**：新建作业会话时必须选择一个项目，未选时禁止列出工程 | MUST |
| FR-SRC-03 | 列出项目下可领取工程（`scope=available`），显示名称、语言、源码文件数、标签、版本、截图 | MUST |
| FR-SRC-04 | 支持按 `q`、`language`、`min_files`、`max_files`、`tag_ids` 在服务端筛选，控制台不本地过滤 | MUST |
| FR-SRC-05 | 领取前必须二次确认，并展示「领取后独占、超时会被回收」的后果 | MUST |
| FR-SRC-06 | 领取成功后立刻下载 ZIP 并解包到暂存区，校验 zip sha256 | MUST |
| FR-SRC-07 | 支持归还（release）与「放弃本题」；放弃时必须先 `cleanup` 容器再归还 | MUST |
| FR-SRC-08 | 已领取但未建任务的工程在控制台有独立「待开工」区，可一键继续 | MUST |
| FR-SRC-09 | 题源不可达时降级为离线模式：仍可查看本地已有任务，但禁止新建 | MUST |
| FR-SRC-10 | 适配器接口可扩展（后续接飞书表、CSV、其他平台） | SHOULD |

### 5.2 建题与题面（PRM）

| 编号 | 需求 | 级别 |
|---|---|---|
| FR-PRM-01 | 建任务时调用 `solo2611.py init --task-name <名> --source <解包目录>`，任务名默认取工程名 | MUST |
| FR-PRM-02 | 提供题面编辑区，实时显示非空字数与 170/240 上限进度 | MUST |
| FR-PRM-03 | 提供难度论证（`difficulty-review.json`）与 ra-人话审核（`ra-renhua-review.json`）的表单编辑 | MUST |
| FR-PRM-04 | 安装题面时调用 `prompt --file ... --task-type ... --difficulty ... --lang ...`，把脚本的 `errors`/`warnings` 原样展示，禁止改写文案 | MUST |
| FR-PRM-05 | 门禁未通过时按钮保持禁用，仅显示「为什么不能过」，不能提供「强制通过」 | MUST |
| FR-PRM-06 | 题面安装后锁定，编辑区只读；如需改必须走「重开本题」并留下原因 | MUST |
| FR-PRM-07 | 题面相似的检测**不自行实现**：技能 `prompt` 已内置 12 字符 shingle 比对与 difflib 相似度（≥0.75 error，≥0.55 warning），控制台只负责把返回的 warnings/errors 原文展示 | MUST |
| FR-PRM-08 | 可一键打开任务目录到 Finder / VS Code，方便外部 Agent 起草 | SHOULD |

### 5.3 快照与仓库（REP）

| 编号 | 需求 | 级别 |
|---|---|---|
| FR-REP-01 | 建任务后提示「初始快照尚未推送」，一键执行 `repo` | MUST |
| FR-REP-02 | 展示初始快照 SHA 与 GitHub permalink，可点击复制 | MUST |
| FR-REP-03 | `repo` 失败（Token 缺失、代理不通、建仓 403）时展示原始错误与修复建议，不吞掉 | MUST |
| FR-REP-04 | 运行结束后自动展示产物快照 SHA、permalink 与 diff 统计 | MUST |

### 5.4 运行（RUN）

| 编号 | 需求 | 级别 |
|---|---|---|
| FR-RUN-01 | 一键 `run`，后台异步执行，实时回显 stdout/stderr 尾部 | MUST |
| FR-RUN-02 | 显示尝试轮次（attempt-N）、当前阶段（拉镜像/启动容器/运行中/导出轨迹/校验） | MUST |
| FR-RUN-03 | 运行中断（超时、容器退出、401）时明确归类，并说明「按规范应重新 roll」还是「换题」 | MUST |
| FR-RUN-04 | 全局容器并发上限可配（默认 4），达到上限时排队并显示队位 | MUST |
| FR-RUN-05 | 同一任务同时只允许一个运行实例（文件锁 + 状态判定双重保险） | MUST |
| FR-RUN-06 | 支持 `interactive` 模式：生成启动命令并复制到剪贴板，运行后提供「已结束，收集」按钮 | MUST |
| FR-RUN-07 | 401/鉴权失败时立即停止整个队列并高亮，不重试烧配额 | MUST |
| FR-RUN-08 | 运行时长超过阈值（默认 90 分钟）时高亮提醒，但不自动杀 | SHOULD |

### 5.5 证据（EVD）

| 编号 | 需求 | 级别 |
|---|---|---|
| FR-EVD-01 | 生成并展示轨迹时间线（调用 `digest`），支持按工具类型折叠与搜索 | MUST |
| FR-EVD-02 | 展示产物 diff（文件列表 + 每个文件增删行数），可展开到全量 diff | MUST |
| FR-EVD-03 | 展示结构校验结果：真人 user 消息数、最终 `stop_reason`、sessionId 唯一性 | MUST |
| FR-EVD-04 | 支持「本机复核」：在产物目录执行用户填写的命令，把输出与退出码记录为证据 | SHOULD |
| FR-EVD-05 | 证据文件可一键在 Finder 中定位、复制绝对路径 | MUST |

### 5.6 录屏（REC）

| 编号 | 需求 | 级别 |
|---|---|---|
| FR-REC-01 | 生成录屏计划（`record plan --mode terminal|web`），提供表单编辑，保存后调 `check-plan` | MUST |
| FR-REC-02 | 列出可用窗口（`record list`），显示 windowId、应用、尺寸、标题，用户必须显式选择 | MUST |
| FR-REC-03 | 启动录制前展示倒计时与「不要切换前台」提示，避免手忙脚乱 | MUST |
| FR-REC-04 | 录制中显示实时计时与剩余秒数（上限 90 秒），提供停止按钮 | MUST |
| FR-REC-05 | 停止后立即展示校验结果：分辨率、时长、采集方式、cursor guard 状态 | MUST |
| FR-REC-06 | Web 题必须先 `chrome-start`，控制台校验窗口 owner pid 与独立实例标记 | MUST |
| FR-REC-07 | 录屏不合格时给出具体原因与补充录制入口，不允许「手动导入」伪装成窗口采集 | MUST |
| FR-REC-08 | 全局同一时刻只允许一个录制（跨任务串行）—— **技能已实现主机级跨任务锁**，控制台只把「另一个任务正在录屏」的报错翻译成提示，不自行加锁 | MUST |

### 5.7 Feedback 与导出（FBC / EXP）

| 编号 | 需求 | 级别 |
|---|---|---|
| FR-FBC-01 | 生成 `feedback.md` 模板并打开编辑器，预填过程/产物两段骨架 | MUST |
| FR-FBC-02 | 保存时自动跑 `feedback --check`，逐条展示 errors/warnings，附规则解释 | MUST |
| FR-FBC-03 | 展示字数、锚点数量、数字密度、过程/产物覆盖四个指标的可视化仪表 | MUST |
| FR-FBC-04 | 记录「谁复核了」：一个必填的复核确认勾选，写入内部记录 | MUST |
| FR-EXP-01 | 单题导出 `export`，生成 19 列 xlsx 并在页面内预览 | MUST |
| FR-EXP-02 | 批量导出 `export-batch`，支持按日期筛选，展示每题的跳过原因 | MUST |
| FR-EXP-03 | 导出前展示 11 项完成度检查，缺项直接列出，不能空白导出 | MUST |
| FR-EXP-04 | 导出的 xlsx 可一键在 Finder 打开、复制路径、下载到浏览器 | MUST |

### 5.8 会话与观测（OPS）

| 编号 | 需求 | 级别 |
|---|---|---|
| FR-OPS-01 | 全局看板：进行中/待办/卡住/今日完成/今日导出，按状态分组 | MUST |
| FR-OPS-02 | 每个任务展示 11 步进度条，当前步骤高亮，失败步骤标红并给出一句话原因 | MUST |
| FR-OPS-03 | 全局事件流（谁在什么时候对哪题做了什么），可筛选 | MUST |
| FR-OPS-04 | 磁盘水位检查：剩余空间低于阈值（默认 30GB）时禁止新开工 | SHOULD |
| FR-OPS-05 | 每日产出统计：已完成题数、导出条数、平均耗时、失败率 | SHOULD |
| FR-OPS-06 | 支持导出「今日工作报告」Markdown，粘贴给 TPM | MAY |

## 6. 非功能需求

| 编号 | 类别 | 要求 |
|---|---|---|
| NFR-01 | 性能 | 首页 20 题规模首屏 < 800ms；状态轮询间隔 3s，单轮开销 < 100ms |
| NFR-02 | 可靠性 | 控制台崩溃不影响正在运行的容器；重启后 10 秒内恢复全部状态 |
| NFR-03 | 一致性 | 磁盘 `state.json` 与 SQLite 不一致时以磁盘为准，自动修正并记事件 |
| NFR-04 | 安全 | 端口只绑 `127.0.0.1`；API Key 存 Keychain 或 0600 文件；日志与界面脱敏 |
| NFR-05 | 可观测 | 每个外部调用记录耗时、退出码、原始输出前 4KB |
| NFR-06 | 可维护 | 技能升级后能探测版本差异，字段缺失时降级展示而不是崩溃 |
| NFR-07 | 可测试 | 所有技能调用可被 mock；单测覆盖核心状态机与门禁判定 |
| NFR-08 | 可移植 | 除录屏外，其余功能在 Linux 上可运行（用于 CI 测试） |

## 7. 关键约束（来自规范，不可协商）

1. 一题一容器一会话，提示词只发一次，不追问。
2. 只收「困难」「地狱」，题面 ≤170 字（上限 240）。
3. 结构不完整必须重 roll，最多 3 次，仍失败换题。
4. 初始快照必须是产物快照的祖先，不 squash、不 force-push。
5. 录屏 720p、≤90 秒、窗口级采集、保留失败片段。
6. 交付完整性 1–5 整数，Feedback 180–280 字（硬上限 360）。
7. 数据不允许返修，抽检不合格会牵连该专家全部历史数据 —— 因此宁可少做，不能蒙。

## 8. 成功判据

- 单人可稳定跑满 20–40 题/天（不含出题构思），无遗漏字段。
- 任一任务从「领取」到「导出」全过程可在控制台内完成，不需要手敲技能命令。
- 导出被质检打回的比例低于 5%，且打回原因不是字段缺失或格式问题。
- 任意时刻能回答：「这题卡在哪一步、为什么、下一步该谁做什么」。
