# v2 · 03 · 开发计划、验收与待决策项

## 1. 前提

- 写法同 v1 `10`：每项任务可直接开工，标注 `ID · 任务 · 产出 · 依赖 · 验收`。
- 基线是当前工作区（含 autopilot、purge、`record auto`），**这些改动尚未提交**；v2 开工前先提交并打 tag `v1.1`。
- 假设 1 个 AI 编码 Agent，每天有效 4–6 小时，总工期 **10–12 个工作日**。

## 2. 里程碑

```
M6  自动交付 2.0        D1–D3     可配置、实时日志、续跑、熔断、预检
```

## 5. 端到端演练

在 v1 `09` §4 的基础上追加一轮「无人值守演练」，用假 Agent 与假技能可全自动执行，
真机至少人工走一次：

1. 预检全绿 → 下计划「目标 3 题」。
2. 观察生产线：三题依次经过起草、运行、交付；日志实时可见。
3. 人为让第 2 题交付阶段失败 → 从本阶段重试 → 成功。
4. 三题完成，其中至少 1 题进入待抽检 → 抽检页通过 1 题、打回 1 题（重写 Feedback）。
5. 被打回的题重新交付并再次抽检通过。
6. 生成提交批次 → 体检通过 → 打开 xlsx 核对 19 列与条数。
7. 清理 1 题 → 撤销 → 再清理 → 在回收站恢复。
8. 重启后端 → 所有状态与重启前一致。

**真实试跑放行门槛**：连续两天，每天计划 ≥ 10 题，抽检打回率 < 20%，批次体检阻断项为 0，
无一次因平台原因（非题目、非模型）导致的失败。

## 7. 待决策项（接 v1 `12` 编号风格）

### 阻塞项

**Q-V2-1 · 默认抽检策略【阻塞 M7】**
全检最稳但每天多花 30 分钟以上；30% 抽样是折中；不抽检风险自担。
**建议**：默认 `sample 30%`，上线第一周用全检，打回率稳定低于 10% 后再降。

**Q-V2-2 · 打回后「重写 Feedback」由谁清理旧稿【阻塞 T7.4】**
硬规矩 3 不允许平台直接写技能任务目录。需要确认技能是否已有重置 Feedback 的子命令。
**建议**：技能新增 `feedback --reset`（与 v1 Q13 建议的 `feedback --save` 一并做）；
在此之前由 Agent 在提示词指引下自行覆盖旧稿，平台只撤销自己的确认记录。

**Q-V2-3 · 提交时录屏等文件怎么交【阻塞 T7.6 的提交包部分】**
目前表内是本机绝对路径。需要向 TPM 确认：是上传到指定存储后填链接，还是随表打包。
**建议**：确认前只做「收拢到一个目录」，不改表内任何内容。
