# solo-auto v4 · solo-2611 技能 0.6 联合升级文档（单次会话 + 自动"继续"）

> 状态：**P0–P2 已实现；真实探针、正常会话和监督器接回已验证。** 日期：2026-11-13。
> 范围：技能 `solo-2611`（当前 0.5.0）与工作台 `solo-auto`（当前 v0.3.0，`dispatch.engine = "v3"`）。
> v1–v3 文档保持原样；v4 只写增量，冲突时以 v4 为准，冲突点列在 `01-requirements.md` §5。

## 一页摘要

目标只有一个：**同样的时间产出更多合格数据**。

现在的做法是"失败就整题重跑，最多 3 次"。统计 `~/claude-runs/solo-2611` 下全部任务后，结论是这种做法浪费很大：

| 现象 | 次数 | 说明 |
|---|---|---|
| 尝试被接受 | 73 | 258 次尝试里的 28% |
| 尝试停在 `running`，再无结果 | 79 | 等结果的脚本断开，模型的工作全部作废 |
| 跑满时限被终止 | 55 | 合计约 70 小时容器时间；有末条时间戳的 54 次全部在终止前 70 秒内仍有输出，模型并没有卡住 |
| 限流（429）后整题重跑 | 32 | 已做的工作作废 |
| 回复截断、停在"接下来我会"、向用户提问 | 17 | 同上 |
| 网关 5xx | 8 | 同上 |

v4 把规则改成：

1. **一题只有一次会话机会**。不再整题重跑。
2. **会话中断时在同一个会话里发"继续"**，最多 2 次。需要第 3 次时终止这道题。
3. **脚本断开不算中断**。模型还在跑就接回去，说一句"继续"即可，不消耗任何次数。

要做到第 2 点，运行方式必须从无头模式（`print`）换成"脚本在后台代替人操作终端"的受管交互模式。
官方镜像不支持恢复会话，这是唯一合规的途径（依据见 `01-requirements.md` §2.3）。

## 三个层面的"继续"

"继续"这个词在三个层面各有一个含义，文档里始终分开写：

| 层面 | 谁发 | 发给谁 | 是否计数 |
|---|---|---|---|
| 会话级 | 监督器自动发，或人工在工作台点按钮 | 容器里的模型 | **计数，上限 2** |
| 任务级 | 你对 Agent（Codex / Claude）说"继续" | Agent 调技能的 `resume` | 不计数 |
| 调度级 | 工作台"恢复"按钮或自动恢复 | 调度内核 | 不计数 |

## 必须先确认的三件事

开发前需要你或项目方给出结论，详见 `01-requirements.md` §6：

1. 带"继续"的数据在本期是否照常收，备注怎么写（建议先交 3–5 条试水）。
2. 容器没建起来、题面还没发出去的失败，是否算用掉了那一次机会（文档默认不算）。
3. 跑满时限的题怎么处理（文档默认直接终止，不发"继续"）。

## 沿用的硬规矩

v1–v3 的十二条全部有效。v4 新增三条：

13. **"继续"只能发字面两个字**，不附带任何提示、纠错或补充要求。
14. **次数上限写死在技能里**（最大 2），工作台和配置只能调低，不能调高。
15. **终止是终态**。被终止的题不能通过改状态文件、重置工作区或换容器再跑一次；只能换题。
