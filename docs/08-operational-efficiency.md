# 08 · 软件操作效率

## 1. 效率的定义

本产品衡量效率不看「界面快不快」，看**一个作业人一天能出多少条合格数据而不出错**。
因此有三个可量化的指标：

| 指标 | 定义 | 目标 |
|---|---|---|
| **有效操作占比** | 花在「判断与写作」上的时间 ÷ 总工时 | ≥ 55% |
| **单题切换成本** | 从「上一题导出」到「下一题进入可运行」的操作数与耗时 | ≤ 12 次操作 / ≤ 90 秒 |
| **手指离键率** | 一次完整流程中必须动鼠标的步数 | ≤ 3 |

第 1 条决定能不能出量，第 2 条决定一天的节拍，第 3 条决定疲劳度。

## 2. 时间去哪了（现状基线）

按一次真实作业拆解，手工敲 11 条技能命令的耗时分段：

| 阶段 | 手工耗时 | 可压缩部分 |
|---|---|---|
| 选题 + 领取 + 下载 | 3–6 min | 领取→解包→建任务可压到 20s |
| 写题面 | 8–20 min | **不可压缩**，创造型工作 |
| 装题面 + 修门禁 | 2–5 min | 门禁在编辑时实时显示，省掉往返 |
| 推送快照 | 1–2 min | 一键，省 1 min |
| 运行（等待） | 25–60 min | 不可压缩，但可**并行** |
| 读轨迹 | 5–12 min | 时间线 + 只读失败 + diff 聚合，省 30% |
| 录屏 | 3–8 min | 计划预填 + 倒计时 + 校验自动，省 40% |
| 写 Feedback | 6–12 min | **不可压缩**，创造型工作 |
| 导出 | 2–4 min | 一键，省 90% |
| 上下文切换/找文件 | 5–15 min | 三栏工作台 + 一键打开目录，省 80% |

结论：**能省的是「等待期间的等待」和「找东西」，不是「想题」和「写反馈」。**
所以设计的核心不是加快界面，而是**让等待时间被别的任务填满**，以及**让所有材料在一个页面内可达**。

## 3. 并行策略（最大的效率来源）

运行一题要 25–60 分钟。串行做，一天 8 小时只能跑 8–10 题。
本产品的设计假设是：**一个人同时推进 4 题，在不同阶段之间跳。**

### 3.1 推荐节拍

```
T+0     题 A 点运行（进入 40 分钟等待）
T+1     题 B 写题面（创造型工作，充分利用 A 的等待）
T+5     题 B 点运行
T+6     题 C 领取 + 建任务
T+8     题 C 写题面 → 运行
T+40    题 A 运行结束 → 读轨迹 → 录屏 → 写 Feedback → 导出
T+45    题 A 完成后，题 D 领取建题
T+48    题 B 运行结束 → 处理 B
...
```

节拍表已内建在看板：**「进行中」区块永远把「等待中（运行）」的任务显示在最上面**，
因为它是唯一「不需要你但现在可以处理别的」的状态。

### 3.2 界面如何支持

| 设计 | 作用 |
|---|---|
| 全局顶栏常驻 `● 运行 3 ● 排队 2` | 不需回看板就知道有没有空闲槽位 |
| 任务完成时 Toast「gb-544 运行结束」+ 点击直达 | 不必轮询 |
| 看板分组「卡住」置顶 | 阻塞项第一眼可见 |
| 任务详情左栏「下一步」按钮 | 从任一题回到该题时，不需要重新判断该做什么 |
| `Esc` 返回时保持列表滚动位置 | 切题不丢位置 |

### 3.3 不做「全自动流水线」的原因（重复 ADR-004 的界面理由）

> v2 修订：本节不再作为实现约束。v2 新增生产线、生产计划、抽检与熔断，见 `docs/v2/01-requirements.md`。

有 4 个槽位不代表可以全自动跑 4 题。出题与 Feedback 是判断型工作，
自动化会把「等待」变成「批量返工」。控制台提供并行**编排能力**，不提供并行**代替判断**。

## 4. 键盘模型

### 4.1 分层优先级

```
全局快捷键（任何时候可用）  >  页面快捷键  >  组件内快捷键（编辑器优先）
```

编辑器（CodeMirror）获得焦点时，除 `⌘K`、`⌘S`、`Esc` 外，所有全局快捷键让位。

### 4.2 全局快捷键

| 键 | 动作 |
|---|---|
| `⌘K` | 命令面板（搜任务、跳页面、执行动作） |
| `⌘S` | 保存当前编辑（题面草稿 / Feedback 草稿 / 表单） |
| `g` 然后 `d/t/s/e/,` | 跳 看板 / 任务列表 / 题源 / 导出 / 设置 |
| `?` | 快捷键帮助浮层 |
| `Esc` | 关闭浮层 → 关闭抽屉 → 退出编辑 → 返回列表（一次一层） |

`g` 前缀有 300ms 窗口，超时作废，且按 `g` 时左下角显示极小提示 `g…`（12px，1.5 秒消失）。

### 4.3 列表 / 表格快捷键

| 键 | 动作 |
|---|---|
| `j` / `k` | 下 / 上一行（同时更新 URL 的 `?sel=`） |
| `Enter` | 打开当前行详情 |
| `Space` | 切换当前行勾选 |
| `x` | 勾选并下移一行（连续批量选择） |
| `⌘A` | 全选当前筛选结果 |
| `/` | 聚焦搜索框 |
| `f` | 切换「只看失败/卡住」筛选 |
| `r` | 刷新（强制重新拉取） |

`j/k` 是列表的主要操作方式：**读 → 判断 → 下一步**，全程不离开键盘。

### 4.4 任务详情快捷键

| 键 | 动作 |
|---|---|
| `1`–`7` | 切换 Tab（概览/题面/轨迹/产物/录屏/Feedback/导出） |
| `⌘Enter` | 执行当前 Tab 的主操作（安装题面 / 运行 / 开始录制 / 检查 Feedback / 导出） |
| `[` / `]` | 上一题 / 下一题（按当前筛选顺序，不离开详情页） |
| `⌘⇧C` | 复制当前 Tab 的关键证据（SessionID / 题面 / 轨迹摘要 / diff 统计） |
| `⌘O` | 在 Finder 打开任务目录 |

**`[` / `]` 是最高频的键。** 处理完一题的 Feedback 后按 `]` 进入下一题，不需要回列表。

### 4.5 编辑器快捷键（题面 / Feedback）

CodeMirror 6 自带外，额外定义：

| 键 | 动作 |
|---|---|
| `⌘Enter` | 安装题面 / 检查 Feedback（同主操作） |
| `⌘⇧K` | 显示检查结果面板 |
| `⌘⇧D` | 插入当前时间戳（写「本次修改」用） |

### 4.6 快捷键不可自定义（首版）

理由：首版只有一个人用，冲突排查成本高于收益。若后续需要，再加 `settings.json` 的 keymap 覆盖。

## 5. 命令面板（`⌘K`）

这是效率设计的核心构件，不是装饰。

### 5.1 能做的事

```
输入即搜：
  gb-544            → 任务（前缀匹配 + 子串匹配）
  > 领取            → 命令：去题源领取
  > 排队全部        → 命令：批量排队已就绪任务
  > 导出今天        → 命令：导出今日
  > 设置            → 跳设置
  ? 录屏            → 帮助：录屏流程
```

### 5.2 结果分组与排序

| 组 | 上限 | 排序 |
|---|---|---|
| 最近访问的任务 | 5 | 最近访问时间 |
| 任务（模糊匹配） | 8 | 状态权重（卡住 > 运行 > 其他）+ 名称匹配度 |
| 命令 | 6 | 使用频率（本地记录） |
| 页面 | 5 | 固定顺序 |

### 5.3 交互细节

- 打开即聚焦输入，默认高亮第一项。
- `↑↓` 或 `⌘j/⌘k` 移动（避免与输入法 `jk` 冲突）。
- `Enter` 执行，`⇥` 补全输入框内容。
- 每条结果显示：图标 + 主文本 + 右侧元信息（状态 / 快捷键）。
- 搜索无结果时给出「没有匹配」+ 最近 3 个任务，不做空建议。

### 5.4 性能要求

200 个任务、50 条命令的匹配必须 < 16ms（同帧完成），保证输入无延迟。
实现：预建小写索引，用 `includes` 而非正则，结果上限 30 条再渲染。

## 6. 批量操作

只对**已 ready 的任务**开放批量（见 ADR-004），具体支持：

| 批量动作 | 前置条件 | 后果提示 |
|---|---|---|
| 批量排队 | 全部 `ready` | 「将占用 4 个容器槽位，其余排队」 |
| 批量检查门禁 | 全部 `prompt_ok` 以上 | 只读，无后果 |
| 批量导出 | 全部 `reviewed` | 「3 题缺录屏，将跳过」并列出 |
| 批量归档 + 归还 | 全部 `exported` | 「先清理容器再归还，不可撤销」 |

**不提供**：批量删除、批量重置、批量安装题面（题面内容各不相同，批量装等于批量犯错）。

### 6.1 批量操作的反馈模式

```
选中 12 项 → [批量排队]
  ↓
顶部出现操作条： 「正在排队 12 个任务 · 已完成 3」
  ↓ 每行左侧出现状态条（info → ok / danger）
  ↓ 结束： 「已排队 9 个，跳过 3 个（缺录屏）」+ [查看跳过详情]
```

- 批量操作**在页面内进行，不跳转、不阻塞**。
- 每个任务的结果独立可见，不合并成「成功 9 / 失败 3」的汇总数字。
- 允许在批量执行中继续操作其他任务（操作条是浮在底部的窄条，不遮挡内容）。

## 7. 点击路径核算

对三条最高频路径做操作数核算（目标：主路径 ≤ 5 次操作）。

### 7.1 领取到可运行（目标 5 次）

| # | 操作 |
|---|---|
| 1 | `g s` 到题源 |
| 2 | 下拉选项目（记住上次选择） |
| 3 | `j` 选中工程 → `Enter` → Modal 确认领取 |
| 4 | 自动下载解包 →「建题」按钮 → 默认名确认 |
| 5 | 「安装题面」前的准备完成，进入题面 Tab |

共 5 次（其中 2 次是键盘）。下载解包与 `init` 期间不做任何询问。

### 7.2 运行结束到导出（目标 8 次）

| # | 操作 |
|---|---|
| 1 | Toast 点击 → 进入该题 |
| 2 | `2` 或点击「轨迹」Tab 读路径（只读，不计操作） |
| 3 | `5` 进录屏 Tab → `⌘Enter` 开始 |
| 4 | 选窗口（列表只有 1–3 个候选，默认第一项，`Enter`） |
| 5 | 倒计时结束，手动作业，`⌘Enter` 停止 |
| 6 | `6` 进 Feedback → 写（不计操作）→ `⌘Enter` 检查 |
| 7 | 勾选复核（`Space`）+ `⌘Enter` 确认 |
| 8 | `7` 进导出 → `⌘Enter` |

### 7.3 题目之间切换（目标 2 次）

`]` → 下一题的详情页。若下一题状态是 `ready`，焦点直接在「下一步」按钮上，`Enter` 即开始。

### 7.4 反例（明确要避免的路径）

| 现有设计若做错 | 操作数 |
|---|---|
| 新建任务要填 8 个字段的表单 | 8+ |
| 每次运行前弹「确认运行？」 | +1/次，无意义 |
| 导出后弹「已导出到…」需手动关闭 | +1，且信息在页面里已有 |
| 录屏前必须先选应用 → 再选窗口 → 再选区域 | 3 层，改为一次选窗口 |
| 门禁错误要点「检查」才显示 | +1，改为编辑时实时 |

## 8. 默认值与记忆

减少输入的关键是**给出正确答案的默认值**：

| 项 | 默认策略 |
|---|---|
| 项目下拉 | 记住上次选择，且默认选中「当前进行中任务所属项目」 |
| 任务名 | `工程名` 去前缀，冲突时追加 `-2` |
| 领域 | `数据工程` / 子方向 `其他`（技能规范默认值） |
| 任务类型 | 上次使用值 |
| 难度 | 上次使用值（但每次必须重新确认难度论证） |
| 语言/框架 | 从工程 ZIP 自动探测（有 `package.json` → Node，`pyproject.toml` → Python） |
| 录屏窗口 | 记忆上次选中的 windowId（同一应用再次出现时高亮推荐） |
| 录制上限 | 90 秒（不可改，规范固定） |
| Feedback 光标位置 | 打开时定位到模板中第一个 `TODO` |
| 导出日期 | 今天 |
| 表格筛选 | 存 localStorage，刷新保持 |

**默认值必须可见且可改。** 不能出现「系统默默填了一个我看不到的字段」。

## 9. 防错设计（比提速更重要）

数据不允许返修，所以**防错优先于效率**：

| 风险 | 设计 |
|---|---|
| 题面超字数 | 实时字数 + 170 处变黄 + 240 处变红并禁用按钮 |
| 装错题面版本 | 安装后锁定只读，改动走「重开本题」并强制填原因 |
| 录屏不合格 | 录制结束立刻校验，不合格时「补录」按钮在大号位置，导出按钮禁用 |
| 重复提交同一 SessionID | 数据库唯一索引 + 导出时二次检查 + 界面在检测到重复时直接报错 |
| 漏勾复核 | 未勾选时导出按钮禁用，且提示「请先逐条复核事实」 |
| 误删 | 所有删除类操作走 dry-run 预览 + 二次输入任务名确认 |
| 401 烧配额 | 队列级熔断（见 FR-RUN-07），并在顶栏常驻一条红色横幅 |

## 10. 效率的度量方式

首版上线后采集三个数（写入 `events`，不做可视化报表，只存数）：

```
1. 每题从「点击运行」到「导出」的墙钟时长
2. 每题的人工操作次数（前端埋点，仅本地）
3. 每题被打回的次数（人工在备注里记录）
```

两周后用这三个数验证是否达到 §1 的目标；不达标时优先优化「单题切换成本」，因为它是唯一不需要改业务流程就能改善的量。

## 11. 不做的事

| 不做 | 原因 |
|---|---|
| 自定义布局 / 拖拽排序看板 | 布局是固定的，拖拽带来不确定性和状态同步负担 |
| 快捷键录制器 / Vim 模式 | 只有一个人用，且已有 `j/k` |
| 批量自动填表 | 涉及判断，等同造假 |
| 离线编辑后同步 | 单机单用户，不需要同步冲突处理 |
| 语音输入 | 题面与 Feedback 都需要精确措辞，语音不可用 |
