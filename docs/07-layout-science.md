# 07 · 布局科学

## 1. 为什么单独写一份

界面「看起来专业」和「用起来快」是两件事，后者的决定因素在布局的数值上：
一行多高、一屏能看几条、眼睛怎么走、鼠标要走多远、切换时视线落在哪。

这一份文档给的是**可以被实现者直接照抄的数值**，不是风格描述。

## 2. 栅格与基线

### 2.1 间距系统

4px 基数，只允许以下 8 个值：

```
4 · 8 · 12 · 16 · 24 · 32 · 48
```

| 用途 | 值 |
|---|---|
| 图标与文字之间 | 6（唯一例外，视觉对齐需要） |
| 行内元素之间 | 8 |
| 表单控件之间 | 12 |
| 区块内部（标题与内容） | 12 |
| 区块之间 | 24 |
| 页面左右外边距 | 24 |
| 页面上下首尾距 | 24 |
| 大区块（页面级）之间 | 32 |

**不允许**：5、6（除图标）、10、14、20、28、36。不整齐的间距是「一眼草稿」的主因。

### 2.2 行高与垂直节奏

正文行高 20，标题行高 24/30，全部是 4 的倍数。

表格行高 44（默认）/ 36（紧凑）：
- 44 = 20（两行文字）+ 12×2（上下内边距），保证双行信息（名称 + 副标题）不用额外样式。
- 36 用于 100 行以上的长表（题源工程列表、导出结果），单行 20 + 8×2。

**不留「半高」中间态。** 一个人只有在两个密度档之间切换，不会出现每张表都不同的行高。

### 2.3 主栅格

```
┌ 24 ┬─────────────── 内容区 ───────────────┬ 24 ┐
```

- 页面最大宽度 **不设上限**（工作台要摊开证据），但内容区最小宽度 960。
- 窗口 < 1280 时，右栏 Inspector 自动折叠为 Drawer。
- 窗口 < 1024 时，左栏 StepRail 变为顶部横向 11 步进度条（见 §6.2）。

### 2.4 三栏宽度（任务详情页）

| 栏 | 宽 | 行为 |
|---|---|---|
| 左 StepRail | 264（固定） | 可拖 220–360，双击复位 |
| 中 主内容 | 自适应，min 520 | — |
| 右 Inspector | 320（固定） | 可拖 280–480，可一键折叠为 0 |

选 264 的依据：`✓ 10 Feedback   246 字` 这样的单行（序号 + 名称 + 右侧细节）在 13px 字号下
需要约 250px，加左右各 12px 内边距 = 274，取整到 264 配合更紧凑的右侧细节排版。
选 320 的依据：SHA 短写（12 位）+ 标签 6 字 + 复制按钮 = 约 300px。

中间栏 520 的下限来自：代码行 13px 等宽，约 78 字符宽，够读 Python 的一行语句。

## 3. 视觉层级与扫描路径

### 3.1 三层，不超过三层

任何页面只有三种视觉权重：

| 层 | 表现 | 用途 |
|---|---|---|
| L1 锚点 | 22px / 600 / `--ink` | 页面标题、当前任务名 |
| L2 内容 | 13px / 400 / `--ink` | 表格、正文、表单 |
| L3 辅助 | 12px / 400 / `--ink-3` | 说明、时间、副标题 |

**没有 L4。** 需要强调时用 `--ink-2` 或加粗，不新增字号。

### 3.2 F 型 + 左对齐

中文界面在密集表格里的实际扫描路径是「左侧标签 → 右侧数值」的反复横向跳跃，
所以**所有 `label: value` 结构一律左对齐、标签固定宽度**，不做右对齐、不做居中。

| 结构 | 标签宽 |
|---|---|
| 右栏 Inspector | 56（如「初始快照」4 字 ≈ 52） |
| 表单（设置页） | 96 |
| 内联说明 | 自适应 + 冒号 |

固定标签宽的好处：值成一条竖线，扫视查错比逐行读快得多。

### 3.3 表格的列顺序

表格列顺序按「**用户判断的顺序**」排，不按数据库字段顺序：

```
名称 → 状态 → 阻塞原因 → 关键数值 → 时间 → 操作
```

- 名称在最左（识别对象）
- 状态紧随（决定要不要关注）
- 阻塞原因第三（解释状态）
- 数值、时间靠右
- 操作最右（鼠标从右往左回来时顺手）

数值列**右对齐**（便于比较大小），文字列左对齐，时间列左对齐（读「34m 前」比对齐更重要）。

### 3.4 一屏信息量预算

以 1440×900（扣除顶栏 48 与页边 48 后约 804 可用高）：

| 页面 | 一屏可见 | 目标 |
|---|---|---|
| 作业看板 | 12–14 个任务行（56 高） | ≥ 12 |
| 任务列表（表格） | 18 行（44 高） | ≥ 18 |
| 轨迹时间线 | 22–26 个步骤 | ≥ 22 |
| 题源工程列表 | 18 行 | ≥ 18 |
| 导出结果 | 18 行 | ≥ 18 |

达不到这个数字，说明行高或内边距超标，必须回调。

## 4. 密度控制

### 4.1 两档密度

```
默认：--row: 44px，内边距 12px
紧凑：--row-dense: 36px，内边距 8px
```

切换入口：表格右上角一个 `[≡]` 图标按钮，状态存 localStorage。
**全局共享一个密度设置**，不按表单独记。

### 4.2 什么时候自动切紧凑

| 场景 | 密度 |
|---|---|
| 题源工程列表（可能 100+ 行） | 紧凑 |
| 导出结果（可能 40+ 行） | 紧凑 |
| 任务列表 | 默认（需读副标题） |
| 看板卡片 | 不适用（双行 56） |
| 轨迹时间线 | 默认（需展开内容） |

## 5. 留白与分割

### 5.1 用线不用影

```
区块之间  → 1px --line 横线
区块内部  → 无缝（靠间距区分）
浮层     → 阴影：0 4px 16px rgba(26,24,21,.10)
```

禁止「卡片套卡片」。一个页面最多一层边框容器。

### 5.2 留白规则

- 文字块之间的间距 ≥ 行高的一半（10）。
- 相邻的两个操作按钮间距 8，不同操作组之间 24。
- 表格与页面标题之间 24。
- **不留「居中留白」** —— 除 EmptyState 外，不存在垂直居中的内容块。

### 5.3 表格的内边距与分隔

```css
th { padding: 0 12px; height: 36px; background: var(--surface-2); border-bottom: 1px solid var(--line); position: sticky; top: 0; }
td { padding: 0 12px; height: var(--row); border-bottom: 1px solid var(--line-soft); }
tr:last-child td { border-bottom: none; }
```

- 无竖线（竖线在 13px 字号下会切成碎片）。
- 无斑马纹（`surface-2` 悬停已足够区分行）。
- 表头 sticky，滚动时必须有 `box-shadow: 0 1px 0 var(--line)` 补足边界（sticky 表头滚过后边框会消失）。

## 6. 响应式与窗口尺寸

### 6.1 断点

只设 3 个断点（这是桌面工具，不做手机适配）：

| 断点 | 行为 |
|---|---|
| ≥ 1440 | 三栏全开 |
| 1280–1439 | 三栏全开，右栏默认 280 |
| 1024–1279 | 右栏折叠为 Drawer（顶部「证据」按钮唤出） |
| < 1024 | 不支持（显示「窗口太小」提示 + 建议尺寸） |

**不做 < 1024 的降级**。理由：这个产品要在 1280 宽以上读 diff，硬塞进 800px 只会两栏都难用。

### 6.2 窄屏的 StepRail 变形

1024–1279 时左栏 264 → 顶部横条：

```
① ② ③ ④ ⑤ ⑥ ⑦ ⑧ ⑨ ⑩ ⑪
```

11 个圆点 + 连线，高 40，当前步实心 + 下方 2px 下划线。悬停显示名称 tooltip。

### 6.3 DPR 与缩放

- 支持系统缩放至 200%，布局按 CSS px 计算，不需要额外处理。
- 在 200% 下若三栏挤压，自动降级为「左栏折叠 + 右栏折叠」，只保留中栏。

## 7. 关键布局数值总表

实现时直接照此设置，不需要再判断：

```css
:root {
  /* 框架 */
  --h-topbar: 48px;
  --w-nav: 56px;
  --w-rail: 264px;
  --w-inspector: 320px;
  --min-main: 520px;

  /* 表格与列表 */
  --row: 44px;
  --row-dense: 36px;
  --th-height: 36px;
  --cell-pad-x: 12px;

  /* 表单 */
  --h-control: 32px;
  --h-control-sm: 28px;
  --w-label: 96px;
  --gap-form: 12px;

  /* 其他 */
  --h-tabs: 36px;
  --h-badge: 20px;
  --w-toast: 320px;
  --w-drawer: 480px;
  --w-modal: 480px;
  --w-code-max: 720px;   /* 代码块在详情页中栏的最大可读宽度 */
}
```

## 8. 布局的六个反模式（本项目明确不做）

| 反模式 | 为什么不做 |
|---|---|
| 卡片网格（每张卡一个任务） | 一屏只能看 6 个，且卡片内空间浪费在留白上 |
| 侧边栏二级菜单折叠树 | 只有 5 个页面，摊开比折叠快 |
| 顶部大标题区（页面名 + 一句描述 + 大留白） | 每天损失 80px 高度，且描述文字没人读 |
| 弹窗内嵌表单（新建任务走 3 层弹窗） | 长流程全部走独立页面，弹窗只用于确认 |
| 右侧抽屉展示详情（在列表页点开） | 详情内容量（轨迹 + diff + 反馈）远超抽屉容量，直接跳页面 |
| 仪表盘式的圆形进度环 | 无法读出精确数值，且占用方形空间 |

## 9. 打印与截图

导出报告（今日工作报告 Markdown、xlsx 预览）需要能被截图贴进群：

- 报告页宽固定 800（A4 宽度 210mm ≈ 794px），单栏，无三栏布局。
- 截图场景下 `--paper` 为白，`--line` 加深到 `#D8D3CB` 保证缩放后仍可见。
- 提供 `POST /api/report/snapshot` 生成一张 HTML 快照（不依赖浏览器截屏）。
