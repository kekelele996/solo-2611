# v3 实现与验收状态

日期：2026-11-11

## 1. 交付结论

v3 已在独立分支 `v3-dispatch-center` 落地为可运行的调度中心。默认新配置使用
`dispatch.engine = "v3"`；把该值改为 `"v2"` 后重启即可回到原生产线，v2 配置键和任务数据均保留。

本次在独立 worktree 开发，没有重启、修改或接管 8099 上正在运行的真实任务。

## 2. 已落地能力

### 配置与回退

- 新增 `[dispatch]` 及 elastic、retry、guard、llm_guard、disk、refill、watchdog、window 子表。
- 首次加载旧配置时按 v2 的容器、起草、交付、在手和磁盘阈值生成 v3 表；再次加载不覆盖用户值。
- 非法手写配置回退默认值并记录告警，不阻止后端启动。
- `SOLO_AUTO_DISPATCH__ENGINE=v2|v3` 可在不修改文件时切换引擎。

### 统一调度内核

- `facts`、`gate`、`probe`、`retry`、`elastic` 五个循环独立心跳。
- Docker 事实通过单飞采集，超时或失败标记为 `unknown`；准入拒绝启动，绝不回落为占用 0。
- 容器、会话、起草、交付、录屏、导出资源池分账；容器预约在容器出现前占用名额。
- 门禁链覆盖总开关、运行意图、定时窗口、全局/范围挂起、启动宽限、Docker、磁盘、上限漂移、容量、启动间隔和项级退避。
- 队列落盘到 SQLite，支持置顶、移动、立即重试、隔离、移出、保留和清理已结束。

### 挂起与自愈

- 挂起包含来源、范围、原因码、下次探测、次数、最长自愈时间和触发任务。
- 人工暂停独立于挂起；自动探测只解除自己来源的挂起。
- 已接入网关、Docker、磁盘、题源、会话、录屏和技能探测器。
- 网关首次失败约 30 秒复测，连续失败达到阈值后挂起；成功一次解除。
- Docker 连续失败挂起容器与录屏范围；磁盘带回滞恢复；题源只影响领取。
- 挂起解除后会把同一故障族导致中断的任务重新排队，并安排 0–60 秒分散重试。
- 15 分钟内出现两次未正常关闭时，新启动登记 `crash_loop` 人工挂起。
- 后端重启后会把仍可跟踪的 ChatGPT 桌面会话重新计入会话池；超过 5 分钟仍找不到 rollout 的会话按 `agent.launch_lost` 退避重试，而不是永久占用名额。

### 失败分类与重试

- `Evidence` 按 `terminated_by → 上下文归因 → 结构化输出 → 容器 → 门禁 → 特征表 → unknown` 分类。
- 默认 `patterns.toml` 在首次启动生成，用户修改后自动热加载；非法正则跳过并告警。
- 瞬时失败进入持久退避，基础设施失败可不计题目次数，仍受单题总尝试上限约束。
- 相同失败指纹、Agent 相同自报原因会直接隔离；工程冷却表结构已建立。

### 界面与接口

- 新增「调度」页：页头状态句、主开关、预设、范围挂起条、队列原因、门禁解释抽屉、调度上限、自动探测、吞吐与守护摘要。
- 新增「调度日志」页：按事件族、级别和任务筛选，展开结构化详情。
- `/production` 显示同一个调度页，旧书签仍可用。
- 顶栏常驻调度状态与容器占用，可一键启停；v2 引擎下界面只读。
- 设置页移除容器、起草、交付和在手上限输入，保留运行超时与尝试次数。
- 调度 API 覆盖状态、上限、策略、队列、挂起、探测、恢复、目标、守护、吞吐、容量和日志。

### 可观测

- `GET /api/health` 返回循环心跳、有效状态、挂起来源和启动记录。
- `dispatch.*` 事件进入现有 SSE 总线；调度日志可按任务串联。
- 吞吐与阶段中位数、容器利用率、容量分钟采样已落表。

## 3. 与设计相比的保守降级

| 项目 | 当前实现 | 原因 / 后续 |
|---|---|---|
| v2 运行进程认领 | v2 的 `Autopilot._load` 仍有旧进程处理路径；v3 调度不会重复启动已登记任务 | 四象限认领需要真实技能进程与容器组合采样；应在 M13 完整补齐后再用于生产 |
| 题源自动重登 | 已登记 `source_guard` 并自动探测可达性；不在本轮反复提交 Keychain 凭据 | 避免错误凭据连续尝试导致账号锁定 |
| 破坏性守护 | 守护框架、仅观察/自动处置开关、命中与手动应用已落地；完整僵尸/孤儿/残留进程清理仍需真实对象归属测试 | 默认 `observe`，未做未经验证的自动终止 |
| 90 条故障矩阵 | 分类、策略、探测和故障注入基础已落地；本轮自动化覆盖核心入口，不等于 90 条全部演练通过 | 真实演练前不能宣称完成 DoD |
| 多项目加权补位 | 目标数据结构与权重字段已保留；当前执行路径仍优先兼容单项目 `IntakeService` | 多项目端到端需与工程台真实领取接口联调 |
| 弹性 429 | 已支持 `retry_delay_ms` / `delay_ms` / `wait_ms` 增量扫描与升降规则；默认关闭 | 真实技能事件字段仍需按 Q-V3-1 做一次实跑确认 |
| `caffeinate` | 配置和状态展示已保留 | 为避免测试/隔离实例改变系统睡眠策略，本轮未启动子进程 |
| 完整 v2 反向导出 | `engine=v2` 保留原数据可运行；在新 v3 队列中产生的条目尚未自动写回 `autopilot.json` | 回退前应先完成活跃项反向导出验证 |

## 4. 待决策项采用的默认

- Q-V3-1：弹性默认关闭，拿不到 429 等待信号时只记录限流提示。
- Q-V3-2：进程死亡且容器存活时保留占用，等待容器结束；不自动改写任务状态。
- Q-V3-3：录屏并发默认 1。
- Q-V3-4：领取幂等以本地 `claims` 与工程台重复领取响应为准。
- Q-V3-5：提交意图有唯一键和 pending 状态；本轮未开启自动重提。
- 守护默认 `observe`；生产建议先观察 48 小时再切 `enforce`。
