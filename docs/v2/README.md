## 一页摘要

v1 解决的是「把 11 条命令变成看板」。实际用下来，人工环节已经被「自动交付」接走，
瓶颈随之换了位置：

1. **自动交付能跑，但看不清、调不了、停不干净。** 参数写死在代码里，日志要点开弹窗手动刷，
   失败后只能整题重来，停止只杀 Agent 不停容器。
2. **没人看过的数据直接进了提交表。** 自动确认的题目与人工复核的题目在导出里没有区别，
   而本期数据不允许返修、抽检不合格会牵连历史数据。
3. **入口还是手工的。** 领取、建题要一题一题点，自动交付只接管了后半段。
4. **任务只进不出。** 回收站没有界面、不会自动清；旧版遗留题混在列表里；磁盘只涨不降。
5. **平台自身状态不透明。** 后端没重启时前端点按钮只得到一个看不懂的报错；设置改了不知道是否生效。

v2 因此分五条线：

| 线 | 一句话 | 里程碑 |
|---|---|---|
| A 自动交付 2.0 | 可配置、可观察、可续跑、可熔断 | M6 |
| B 抽检与质量 | 自动交付的题先进抽检队列，批次体检后再出表 | M7 |
| B′ 使用统计 | 每个项目/工程的使用次数、交付次数、提交次数，清理任务后仍保留 | M7 |
| C 一条龙入口 | 「今天要 N 题」→ 自动领取、建题、交付 | M8 |
| D 任务生命周期 | 回收站、自动瘦身、孤儿与旧版任务处理 | M9 |
| E 平台体验与工程债 | 版本握手、常驻、通知、收件箱、契约检查修复 | M9–M10 |

预计 **10–12 个工作日**，M6、M7 优先级最高，可以只做这两个里程碑就上线。
