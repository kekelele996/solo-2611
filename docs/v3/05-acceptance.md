# v3 · 05 · 验收文档

## 1. 验收方式总则

- 每条用例三要素：**前置 → 操作 → 期望**。期望必须是可观察的：接口返回、事件表里的事件、界面文字、容器列表、文件内容。
- 用例编号前缀与 `04-dev-plan.md` 的「验收」列一致；§3 的编号与 `03-failure-playbook.md` §4 的情形编号一一对应。
- 自动化程度标注：**自** = 必须有自动化测试（进 `make check`）；**演** = 用演练脚本在隔离数据目录执行并留记录；
  **真** = 必须在真实技能 + 真实 Docker 上人工执行一次。
- 所有演练在隔离目录进行：`SOLO_AUTO_HOME=/tmp/solo-auto-accept`，不触碰真实任务目录与真实领取。
- 静态检查沿用 v1 / v2 全部规则，追加四条 grep 规则：
  1. `dispatch/` 之外不得出现对 `docker ps` 的直接调用（统一经 `facts.py`）；
  2. 除 `holds.py` 的人工入口外，不得出现把 `desired_state` 赋值为 `running` 的代码路径；
  3. 后端不得出现直接改写任务 `state.json` 的 `status` 字段的代码（只允许经技能命令）；
  4. `guards/` 内每个会产生破坏性动作的函数必须先调用 `require_enforce()`。

## 3. 故障注入矩阵

### 3.1 注入点

`dispatch/faults.py` 仅在环境变量 `SOLO_AUTO_FAULTS=1` 时生效，正式运行时所有注入点为空操作。

| 注入点 | 可注入的行为 |
|---|---|
| `docker.ps` | 失败 / 超时 n 秒 / 返回指定容器列表 / `-a` 失败而普通成功 |
| `docker.inspect` | 指定退出码、`OOMKilled` |
| `disk.free` | 返回指定剩余空间 |
| `fs.write` | 指定路径写入抛 `OSError` |
| `clock` | 挂钟跳变（模拟睡眠）、回拨 |
| `probe.llm` | 成功 / 超时 / 401 / 模型名不符 |
| `skill.run` | 指定耗时、退出码、stderr、是否产生容器、是否写入进展 |
| `skill.collect` / `cleanup` / `record` / `export` | 成功 / 失败 |
| `agent` | 假 Agent：指定耗时、结论行、日志节奏、是否挂住 |
| `desktop` | 深链接丢失、rollout 终止类型、用量受限文本 |
| `source` | 401 / 409 / 5xx / 空列表 / 下载失败 |
| `github` | 瞬时失败 / 401 / 限流 / 仓库已存在 |
| `submit` | 失败 / 401 / 已存在记录 / 未通过 |
| `sqlite` | 写入抛锁错误 n 次 |
| `loop.<name>` | 某循环挂住 n 秒 / 抛异常 |
| `process.kill` | 在指定事件之后杀掉后端 |
